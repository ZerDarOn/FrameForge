## 1. 产品目标与范围

将现有“AI 动画帧审查工具”转为通用像素帧动画编辑器。用户能自己绘制或修改素材，也能生成、导入素材，然后抽帧、修帧、调整位置与动作节奏，最后导出可用动画。

核心流程：导入或生成角色动作 → 选取 8 帧 → 清理背景 → 修改错误像素 → 对齐脚底 → 调整关键帧停留时间 → 循环预览 → 导出 PNG 序列或精灵图。

本轮范围包括：项目与素材保存、动作/图层/帧组织、批量编辑、像素绘制、素材处理、生成接入和可靠导出。骨骼绑定、蒙皮、人体运动生成、自回归扩散研究、3D、团队协作、支付账户体系不进入实施范围。现有 AI 位移/闪烁审查保留兼容，降低开发优先级。

不要因为参考软件有某项功能就扩展范围；不要先改视觉外观，也不要整套拼接多个开源仓库。

## 3. 架构决策

### ADR-1：保留技术栈，逐步替换核心

- 保留 React 19、TypeScript、Zustand、Tauri 2、Rust、SQLite，尽量复用桌面壳、窗口、面板、文件访问和供应商适配。
- 相比直接 fork Pixelorama，当前方案减少整栈迁移；代价是需要自己完成像素编辑核心。
- 用旧项目导入适配和新文档版本进行替换，不长期维护两套互相写入的状态。
- 回退：保留旧项目副本与源文件，新格式迁移失败不更改旧格式。

### ADR-2：统一动画文档和编辑入口

- TypeScript 编辑核心负责当前文档、编辑命令、历史和时间求值；React 负责交互展示，Zustand 提供订阅，不在组件中散落数据库调用。
- Rust 负责文件、SQLite、任务与输入验证，通过明确的文档保存协议持久化。
- 所有编辑入口调用同一命令：画布拖动、属性输入、快捷键和后续自动化调用行为一致。
- 序列化保存请求，携带 project/document ID 与 revision；拒绝旧版本覆盖。第一版可采用有界文档快照，像素内容单独存储，避免每次复制所有位图。
- 保存状态必须可见。保存失败保留未保存文档供重试；不显示成功，不静默覆盖较新状态。撤销/重做后的文档同样进入保存流程。

### ADR-3：统一画面求值与输出规则

- 使用一个公共合成入口定义给定动作与时间应显示哪些图层、像素内容、变换和不透明度。
- 首期优先 Canvas 2D 公共合成实现，供画布、播放、洋葱皮和导出复用；PixiJS 如用于交互显示，也必须遵循同一场景数据和坐标契约，不独立解释时间线。
- 默认整数像素移动、最近邻采样；旋转质量可后续优化，不能以“像素完美”描述未经验证的任意角度旋转。
- 坐标锚点、旋转单位、变换顺序、透明背景、图层顺序和输出原点必须明确且测试固定。同一动作所有输出帧使用统一画布和原点。
- 代价：大图性能需要测量。先保证一致性，不提前同时实现 CPU/GPU 两套独立渲染器。

## 4. 模块与数据模型

| 模块 | 唯一责任 |
| --- | --- |
| 素材库 | 原图、处理版本、生成来源、项目引用与文件生命周期 |
| 动画文档 | 动作/方向分组、图层、时间步、画格、原点与调色板 |
| 编辑核心 | 命令、选区、像素修改、历史、批量原子操作 |
| 渲染与画布 | 时间求值、坐标转换、合成、预览和洋葱皮 |
| 处理与生成任务 | 导入解码、抽帧、切图、抠图、清理、生成与任务状态 |
| 保存与导出 | 文档版本、数据库迁移、文件提交、动画打包与元数据 |

建议的新模型（名称是设计概念，代码命名由实施者按仓库规范确定）：

- Material：独立素材身份、来源、原始文件、当前处理版本；可被多个项目引用。
- ContentRevision：不可变像素内容/图片版本；多个画格可引用，普通复制后编辑应写入新版本，避免意外联动。
- AnimationDocument：schemaVersion、revision、画布尺寸、调色板、动作与图层数据。
- Animation：动作名称、可选方向、FPS、播放方式、有序 Steps。
- Step：稳定 ID、顺序、正整数 durationTicks。图层共享时间步，空画格合法。
- Layer：稳定 ID、顺序、可见、锁定、不透明度。
- Cel：引用 layerId + stepId，引用内容版本，携带位置/缩放/旋转等实例变换。
- UIState：当前工具、选择、缩放、播放头；与应保存的作品内容明确区分。

时间契约：Step 顺序展开为累计 tick 区间，区间采用左闭右开；时长为 durationTicks / FPS。删除/抽帧提供“压缩总时长”或“保持总时长”的明确选择。素材源时间戳只用于溯源，不能兼任时间线索引。

旧项目转换：按旧 startFrame 和 durationFrames 展开时间覆盖，保留空白区间、顺序、变换和原图引用；冲突数据明确报告，不能无提示丢帧。将外部文件复制为受管理素材时验证成功后再切换引用，丢失文件列出修复入口。

## 6. 风险约束与测试

1. 不变量：ID 唯一、图层/时间步引用有效、时长正整数、数值有限、同一 layer+step 的内容规则唯一；共享原点，不因单帧裁剪导致新增抖动。
2. 原子性：批量编辑是一条命令；数据库和文件通过“先准备文件、后提交引用”避免部分保存；失败临时文件可清理，已引用内容不能误删。
3. 并发：项目加载、保存、生成任务绑定身份与版本；项目切换丢弃旧响应；保存按序，不让旧请求回写新内容。
4. 副作用：迁移保留副本；生成候选由用户采用；删除项目/导出覆盖遵循已有授权和明确交互。
5. 信任边界：后端验证尺寸、帧数、路径和变换参数；API Key 仅后端保存和使用，所有配置返回路径都应脱敏；外部程序用参数数组调用。
6. 可观测性：导入/保存/导出/生成记录操作或任务 ID、阶段、数量、时长和错误；界面显示未保存/失败状态，日志不能包含密钥或整张图像。
7. 性能：不要每次 pointermove 深拷贝所有位图；缩略图/纹理缓存有预算；长任务可取消且不阻塞交互；先测代表性帧数，再按瓶颈优化。

必要测试：

- 命令与逆操作、批量原子性、复制后像素修改不污染源内容。
- Step 时间映射、空画格、长停留、抽帧两种节奏策略。
- 保存/重开/撤销后保存、迁移失败、缺失源图、旧请求跨项目返回。
- 用固定小图比较公共渲染与导出结果；验证旋转、图层透明度、隐藏和统一原点；GIF 验证时长量化容差。
- 桌面真实走通导入→编辑→保存→重开→导出；浏览器单测不能冒充 Tauri 集成验证。
- 类型检查、前端构建、Rust check/test；实际环境缺少工具链时明确阻塞，不能声称通过。
